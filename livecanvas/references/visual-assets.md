# 图片、PNG 与 emoji

## 选素材

默认主动加入能识别主题、参与叙事的视觉素材。按内容选一组风格统一的素材，不强制同时使用照片、PNG 和 emoji，也不因为暂时缺某张图而搁置整个制作。

- 用户提供的图片优先；其次查官方产品/媒体素材、来源与使用条件清楚的图片或图标。需要找实际图片时使用可用的图片搜索，打开来源页核对对象、年代、版本与可用方式。
- 产品对比优先同视角透明 PNG；城市与季节适合照片或背景插画；抽象数量和生活场景可用 emoji、原创 SVG 或许可明确的图标。
- 保留清楚的主体和边缘，选足够分辨率的原图。透明棋盘格不等于真实 alpha；不能拉伸图像、误用带白底文件为抠图，也不去除水印。
- 没有合适实物图时可用明确标为示意的原创插画或 emoji，不伪造官方产品外观、品牌标志、地理路线或真实现场。如需要生成/编辑栅格图片，使用当前可用的图片生成工具并遵守其要求。
- 素材能够识别主题，也应参与动作：杯子随门店卡片成组出现、列车沿年份移动、奖牌随届次落位、太阳和雪花随月份切换。少量图片有作用，比堆满素材更好。

## 本地资源与追溯

获准使用且允许获取的素材保存到本次工程 `public/media/`，最终渲染优先从本地读取，避免临时链接失效。不要通过下载绕过工具的媒体访问或显示限制。

使用素材时保存 `assets.json`，每项记录：`id`、`kind`、`localPath`、来源页面 `sourceUrl`、作者/提供者、使用条件或许可、改动、`role`（主体/场景/解释/装饰）、如有的示意或生成标记。用户提供/原创/emoji 也分别标明，不编造来源链接。来源或使用条件不明时换用可确认素材；按要求保留署名。来源页面与图片文件 URL 区分记录。

素材与项目一起交付，不把机器绝对路径写进 composition。数据和事实仍在 `data.json` / `sources.md`，图片本身不是数值证据。

## Remotion 加载

- PNG/JPEG/WebP/SVG 用 Remotion 的 `Img` 和 `staticFile('media/...')`；不要用原生 img 或 CSS 背景图片绕过加载等待。CSS 渐变不受此限制。
- 图片层的宽高、objectFit 和 transformOrigin 明确设置。产品抠图通常 contain；场景照片可以 cover，但逐帧检查重要内容不被裁掉。
- 静态 emoji 可以用文本元素渲染；指定可用 emoji 字体回退并检查实际帧，不假设所有机器有同一套彩色字形。使用文字呈现时记录字符和字体环境。需要跨机器一致时使用许可明确的本地 PNG/SVG emoji 素材，不把系统 emoji 字形当作任意可再分发的素材包。
- GIF/APNG 等自带动画不能自由播放；转成与 Remotion 帧号绑定的资源或使用支持确定性帧控制的组件。无需动的资源优先使用静态图。
- 图片层也全部用 `useCurrentFrame()` 驱动。PNG 的位移、遮罩揭示、层次视差与数字动画同步，封面时落在最终可读位置。

## 验收

看实际输出：素材是否真的出现；emoji 是否变成方框；透明边缘是否有白边；图片与数字是否对应；过渡是否闪空帧；主体是否遮挡来源或主数字；封面能否独立讲清内容。仅通过类型检查不能代替图片验收。
